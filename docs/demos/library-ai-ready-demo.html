🤖 Making the Library App AI-Ready with SQL Server 2025

Duration: ~15 minutes

🎬 Scenario Introduction

I've been asked to add AI-powered semantic search to our existing Library app. The app is built with Node.js and Sequelize, but instead of modifying the ORM layer, I'll enhance the database directly using SQL Server 2025's new VECTOR capabilities.

Before writing any code, I'll show you the spec-driven development approach: how a PRD and custom instructions shape the way GitHub Copilot generates code for this project. Then we'll make the database AI-ready.

In this demo, I'll show you how to:

  • Use a PRD and GitHub Copilot custom instructions to guide AI-generated code
  • Use GitHub Copilot in VS Code to understand the schema and generate the SQL to add VECTOR support
  • Run Python scripts (already prepared) to generate and store embeddings
  • Demonstrate semantic search using SQL Server 2025's native vector similarity functions

🎤 Voiceover: "For this demo, I've already set up the environment -- Python packages are installed, the .env file is configured with my SQL Server connection string, Ollama is running with the nomic-embed-text model, and the code is ready. 🔹 Step 11: Walk Through the Vector Search Code

🎤 Voiceover: "That was fast! Let me show you exactly where that magic happens in the code."

Show: Open app/backend/ai/chat_service.py in VS Code and walk through these sections:

  • Line ~456 — search_similar_books() — This is the core function. It takes the user's question embedding and runs a vector similarity search in SQL Server.
  • Lines ~577-603 — The VECTOR_DISTANCE query — The actual SQL that powers everything: 
    WITH VectorScores AS (
    SELECT
        b.id, b.title, b.category, b.year,
        1 - VECTOR_DISTANCE('cosine', b.description_embedding,
            CAST(? AS VECTOR(768))) AS SimilarityScore
    FROM books b
    WHERE b.description_embedding IS NOT NULL
)
SELECT TOP (?)
    vs.id, vs.title, vs.category, vs.year,
    STRING_AGG(CONCAT(a.first_name, ' ', a.last_name), ', ') as author_name,
    vs.SimilarityScore
FROM VectorScores vs
LEFT JOIN books_authors ba ON vs.id = ba.book_id
LEFT JOIN authors a ON ba.author_id = a.id
GROUP BY vs.id, vs.title, vs.category, vs.year, vs.SimilarityScore
ORDER BY vs.SimilarityScore DESC
  • Line ~90 — LIBRARIAN_SYSTEM_PROMPT — The guardrail: "Recommend books ONLY from the list below. NEVER invent books." This prevents hallucination.
  • Line ~657 — generate_response_with_rag() — The RAG orchestration: filter by similarity threshold, build a constrained prompt, call the LLM, then validate the response.

🎤 Voiceover: "The key insight is that VECTOR_DISTANCE runs entirely in SQL Server -- no external vector database needed. The CTE calculates cosine similarity for every book, then we join authors and return the top matches. The system prompt and validation layer ensure the LLM only recommends books that actually exist in our database."
