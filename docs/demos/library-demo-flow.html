📚 Library App Demo – MSSQL for VS Code + SQL database in Fabric + GitHub Copilot

🎬 Intro

Hi! I’m Carlos Robles, Principal Product Manager on the SQL Developer Experiences team. In this video, I’ll walk you through version 1.32 of the MSSQL extension for VS Code.

This release marks the General Availability of our new UI, introduces the Schema Designer for visual schema editing, and brings GitHub Copilot integration for an AI-assisted SQL development experience — all inside VS Code.

🎬 Scenario

In this scenario, I’m a developer working on a full-stack app that uses Node.js and Sequelize. I’ve been asked to add a new feature to manage magazines in our system and to use SQL Database in Microsoft Fabric as our backend platform. I’m comfortable with ORMs but still new to Sequelize, and only have basic familiarity with T-SQL. I want to use GitHub Copilot and the MSSQL extension to evolve my database schema quickly and efficiently—all from inside VS Code.

“Let’s switch over to Visual Studio Code. I’ve already got the MSSQL extension installed and configured, and I’m also signed in to GitHub Copilot with my GitHub account and subscription.”

1. App Environment Ready (duration: 30 seconds)

“Before we start, I would like to say that my environment is already set up. All required dependencies are installed and the CLI tools like npm, node, and npx are available.”

2. Provision Infrastructure with Terraform (duration: 1 minute)

“I also already created the Terraform scripts to provision my SQL database in Fabric, and gone through initialization, planning, and applying. Now I’ll show the output values — particularly the connection details I’ll use next.”

terraform -chdir=infrastructure output

3. Configure Your Environment (duration: 1 minute)

“Let’s grab the server fully qualified domain name, database name, and the standard connection string format directly from the Fabric REST API. We’ll use these in our environment configuration.”

curl -s https://api.fabric.microsoft.com/v1/workspaces/$WORKSPACE_ID/sqlDatabases \
  -H "Authorization: Bearer $FABRIC_TOKEN" \
  | jq -r '.value[0].properties | .serverFqdn, .databaseName, .connectionString'

4. Start the backend app (duration: 1 minute)

“When I start the backend, Sequelize creates the tables automatically from my model definitions.”

cd app/backend
npm start

5. Seed the database (duration: 1 minute)

“I’m using Sequelize CLI to seed the database with realistic test data. I will open a new terminal for this.”

cd app/backend
npx sequelize-cli db:seed:all

6. Start the frontend app (duration: 1 minute)

“Now the backend and frontend are up. I can load the UI in the browser.”

cd app/frontend/library-frontend
npm start

7. Open the app in VS Code’s browser preview (duration: 30 seconds)

“Now that both services are running, I’ll preview the app using VS Code’s simple browser. The backend is on port 3000 and the frontend is on port 3001.”

Backend: 
http://localhost:3000
Frontend: 
http://localhost:3001

8. Connect to Fabric SQL with MSSQL Extension (duration: 1 minute)

“Now let’s take a look at the database in the Fabric portal. Notice there’s an ‘Open in VS Code’ button that launches the MSSQL extension directly from here.”

📌 Show: Connection dialog, and Object Explorer (OE) super brief.
