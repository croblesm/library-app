Schema Designer + GitHub Copilot Demo

Duration: ~15 minutes

🎬 Scenario Introduction

I'm a developer working on a Library management app built with Node.js, Sequelize, and React. I've been asked to add a new feature to manage magazines. The frontend already has a Magazines page showing hardcoded data, and my task is to create the backend infrastructure: the database table, relationships, test data, and a REST API endpoint.

Instead of writing SQL by hand, I'll use the Schema Designer in the MSSQL extension for VS Code, with GitHub Copilot integrated directly into the visual editor. Then I'll use Data API Builder (DAB) to expose the new table as a REST API in seconds.

🔹 1. Show the App with Hardcoded Magazines

🎤 Voiceover: "Let me start by showing you the app. We already have a Books page and an Authors page. Recently, I added a Magazines page, but right now it's using hardcoded data in the React frontend. My goal is to create the real database table and wire it up."

Show: Open the frontend at http://localhost:3001/magazines and browse the 5 hardcoded magazine cards.

🔹 2. Open Schema Designer

🎤 Voiceover: "Now let's create the actual table. I'll open the Schema Designer from the MSSQL extension. This gives me a visual editor where I can design tables, add columns, and define relationships -- all without writing a single line of SQL."

Show: Right-click the database in Object Explorer > Open Schema Designer. Show the existing tables (books, authors, books_authors) in the visual view.

🔹 3. Use GitHub Copilot to Create the Magazines Table

🎤 Voiceover: "Here's where it gets interesting. Instead of typing out the schema manually, I'll go to my React frontend code -- ModernApp.js -- and select the hardcoded JSON data for magazines. Then, right here in the Schema Designer chat, I'll ask GitHub Copilot to create the table from that selection."

Show: Open ModernApp.js, select the MAGAZINES_DATA array, then switch to the Schema Designer chat panel.

using the selected JSON structure, create a new table called Magazines

🎤 Voiceover: "This is the key moment -- GitHub Copilot picked up the context from my JavaScript file and used it to create the database table. It understood the JSON structure, inferred the correct SQL Server data types, and followed the project's lowercase naming conventions. That's cross-file context awareness at work."

🔹 4. Review Changes in the Visual Editor

🎤 Voiceover: "The Schema Designer shows me a visual diff of what's about to change. I can see the new magazines table with all its columns, data types, and constraints. I'm in full control -- I can adjust anything before committing."

Show: The "Copilot Changes" tab at the bottom showing "Added Table: [dbo].[magazines]" with Accept/Undo options. Click through the columns to verify: id (INT, PK, Identity), title (NVARCHAR), issue (INT), year (INT), category (NVARCHAR).

🔹 5. Publish Changes to Database

🎤 Voiceover: "Everything looks good. Now I'll click Publish to apply these changes to the actual database. The Schema Designer generates and executes the DDL statement for me."

Show: Click "Publish Changes" button. Show the confirmation and the table appearing in Object Explorer.

🎤 Voiceover: "GitHub Copilot creates a magazines_authors junction table with the correct foreign keys pointing to both tables. Let me review and publish this change too."

🔹 8. Open Data API Builder

🎤 Voiceover: "Now for the final piece -- I need a REST API for the frontend to call. Instead of writing Express routes and Sequelize models, I'll use Data API Builder to create an endpoint in seconds. DAB reads my database schema and exposes it as a REST API automatically."

Show: Open the Data API Builder configuration from the MSSQL extension. Notice it picked up all 5 entities from the dbo schema: authors, books_authors, magazines_authors, books, and magazines -- all with full CRUD enabled.

🎤 Voiceover: "DAB automatically detected all the tables in my schema. But I only need the magazines endpoint for now, and I want it read-only. Let me ask GitHub Copilot to clean this up."

🔹 9. Configure the API with GitHub Copilot

🎤 Voiceover: "Instead of manually unchecking entities and toggling permissions one by one, I'll ask GitHub Copilot to do it for me."

Remove all entities from the dbo schema and keep only the magazines entity. Make it a read-only endpoint -- I only need the Read permission enabled.

🎤 Voiceover: "Done -- GitHub Copilot removed the other entities and set magazines to read-only. Now I just need to deploy it."

Show: The DAB configuration now shows only the magazines entity with only the Read checkbox enabled. Click Deploy.

🎯 What We Accomplished

In this demo, we went from a hardcoded frontend to a fully connected stack:

  • Used Schema Designer to visually create the magazines table
  • Used GitHub Copilot integrated in Schema Designer to generate table structures from JSON
  • Added a many-to-many relationship with the existing authors table using GitHub Copilot
  • Generated science-themed test data with GitHub Copilot
  • Created a read-only REST API using Data API Builder, configured with GitHub Copilot
  • Wired the React frontend to the live API endpoint

Key takeaways:

  • Schema Designer + GitHub Copilot lets you design tables visually with AI assistance
  • You stay in control -- review and approve every change before publishing
  • Data API Builder eliminates boilerplate API code for standard CRUD operations
  • The entire workflow happens inside VS Code -- no context switching
