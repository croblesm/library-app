Schema Designer + GitHub Copilot Demo

Scenario Introduction

I'm a developer working on a Library management app built with Node.js, Sequelize, and React. I've been asked to add a new feature to manage magazines. The frontend already has a Magazines page showing hardcoded data, and my task is to create the backend infrastructure: the database table, relationships, test data, and a REST API endpoint.

Instead of writing SQL by hand, I'll use the Schema Designer in the MSSQL extension for VS Code, with GitHub Copilot integrated directly into the visual editor. Then I'll use Data API Builder (DAB) to expose the new table as a REST API in seconds.

Step 1: Show the App with Hardcoded Magazines

"Let me start by showing you the app. We already have a Books page and an Authors page. Recently, I added a Magazines page, but right now it's using hardcoded data in the React frontend. My goal is to create the real database table and wire it up."

Show: Open the frontend at http://localhost:3001/magazines and browse the 5 hardcoded magazine cards.

Step 2: Open Schema Designer

"Now let's create the actual table. I'll open the Schema Designer from the MSSQL extension. This gives me a visual editor where I can design tables, add columns, and define relationships -- all without writing a single line of SQL."

Show: Right-click the database in Object Explorer > Open Schema Designer. Show the existing tables (books, authors, books_authors) in the visual view.

Step 3: Use Copilot to Create the Magazines Table

"Here's where it gets interesting. Instead of manually adding columns one by one, I'll ask GitHub Copilot -- right here in the Schema Designer -- to create the table for me based on a JSON sample."

Create a new table called magazines that matches this JSON structure. Use clean T-SQL best practices:
{
  "id": 1,
  "title": "Tech Monthly",
  "issue": 1,
  "year": 2025,
  "category": "Science"
}

"Notice how Copilot understood the JSON and created the table with appropriate data types -- INT for id with identity, NVARCHAR for strings, INT for numbers. And it followed the project's lowercase naming conventions."

Step 4: Review Changes in the Visual Editor

"The Schema Designer shows me a visual diff of what's about to change. I can see the new magazines table with all its columns, data types, and constraints. I'm in full control -- I can adjust anything before committing."

Show: The "Copilot Changes" tab at the bottom showing "Added Table: [dbo].[magazines]" with Accept/Undo options. Click through the columns to verify: id (INT, PK, Identity), title (NVARCHAR), issue (INT), year (INT), category (NVARCHAR).

Step 5: Publish Changes to Database

"Everything looks good. Now I'll click Publish to apply these changes to the actual database. The Schema Designer generates and executes the DDL statement for me."

Show: Click "Publish Changes" button. Show the confirmation and the table appearing in Object Explorer.

Step 6: Add a Many-to-Many Relationship with Authors

"Magazines can also have authors, just like books do. Let me ask Copilot to create the junction table for this many-to-many relationship."

Add a many-to-many relationship between this new magazines table and the existing authors table.
Ensure that the foreign key columns align with the current database schema for both tables, using the correct primary key columns as defined in the existing structure.

"Copilot creates a magazines_authors junction table with the correct foreign keys pointing to both tables. Let me review and publish this change too."

Step 7: Generate Science-Themed Test Data

"Now I need some test data. Let me ask Copilot to generate realistic INSERT statements for our new table."

Generate sample INSERT statements for the magazines table.
- Each magazine should be themed around science or technology (e.g., astronomy, physics, biology, robotics).
- Include at least 5 magazines with creative titles, different issues, and years.
- Make sure the INSERT statements follow typical SQL conventions, leaving out any auto-generated columns.
- Then, link each magazine to one or more existing authors in the authors table using the junction table.

Step 8: Set Up a REST API with Data API Builder

"Now for the final piece -- I need a REST API for the frontend to call. Instead of writing Express routes and Sequelize models, I'll use Data API Builder to create an endpoint in seconds. DAB reads my database schema and exposes it as a REST API automatically."

Show: Open the Data API Builder configuration from the MSSQL extension. Select the magazines table and enable REST API with all CRUD operations. Show the configuration UI with entity name, source table, and permissions.

"With one click, I've got a fully functional REST API for magazines. DAB handles all the CRUD operations, pagination, filtering, and even supports OData queries out of the box."

Step 9: Wire the Frontend to the DAB Endpoint

"Now I just need to update the frontend to fetch from the DAB endpoint instead of using hardcoded data. Let me show the quick change in ModernApp.js."

Show: In ModernApp.js, replace the MAGAZINES_DATA constant with an API call to the DAB endpoint. The MagazinesPage component already supports receiving data as a prop.

// Before: hardcoded data
const MAGAZINES_DATA = [
  { id: 1, title: "Tech Monthly", ... },
  ...
];

// After: fetch from DAB endpoint
const [magazines, setMagazines] = useState([]);
useEffect(() => {
  axios.get('http://localhost:5000/api/magazines')
    .then(res => setMagazines(res.data.value))
    .catch(err => console.error(err));
}, []);

Step 10: Verify in the App

"Let me refresh the app and navigate to the Magazines page. Now we're seeing live data from the database, served through DAB, displayed in our React frontend. The full stack is connected."

Show: Refresh the frontend at http://localhost:3001/magazines. The magazine cards now show the science-themed data we inserted from the database.

What We Accomplished

In this demo, we went from a hardcoded frontend to a fully connected stack:

  • Used Schema Designer to visually create the magazines table
  • Used GitHub Copilot integrated in Schema Designer to generate table structures from JSON
  • Added a many-to-many relationship with the existing authors table
  • Generated science-themed test data with Copilot
  • Created a REST API in seconds using Data API Builder
  • Wired the React frontend to the live API endpoint

Key takeaways:

  • Schema Designer + Copilot lets you design tables visually with AI assistance
  • You stay in control -- review and approve every change before publishing
  • Data API Builder eliminates boilerplate API code for standard CRUD operations
  • The entire workflow happens inside VS Code -- no context switching
